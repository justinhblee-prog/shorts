# BUILD-00023 — Upload policy check-date freshness

**Status:** Merged to `main`; PR CI passed

## Problem

The upload-time policy gate previously checked the policy rule version but did not require the recorded policy check date to match the active local policy check date. A stale check date could therefore be represented as fresh when audit stamps were written.

## Change

Before an upload attempt is initialized, the upload store now requires both:
- The current script artifact's `policy_preflight.policy_version` and `policy_checked_on` to match the active `POLICY_VERSION` and `POLICY_CHECKED_ON`.
- The latest human-approved script snapshot to contain the same active version and check date.

Missing, malformed, or stale policy evidence is rejected before the remote YouTube API request. Existing human approval, private-only upload behavior, and duplicate-upload reconciliation safeguards remain unchanged.

## Regression coverage

- Reject stale current script policy check date.
- Reject stale policy check date embedded in the human-approved artifact snapshot.
