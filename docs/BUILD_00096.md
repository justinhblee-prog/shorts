# BUILD-00096 — unique fencing tokens for YouTube metrics collector leases

## Problem
The YouTube Data API metrics collector lease used only the process owner ID as its renewal and state-write fence. Repeated acquisitions by the same owner could overwrite the live lease, and a stale run from that owner could renew or write state after a newer acquisition. This also allowed overlapping acquisitions by the same owner because the acquire guard only rejected a different owner.

## Changes
- Add a unique token for every lease acquisition, with a migration for existing databases.
- Block every unexpired lease, including one requested by the same owner.
- Require the exact owner/token pair for renewal, release and collection-state writes.
- Pass the acquisition token through the collector heartbeat and every state transition.
- Add regression coverage for same-owner exclusion, stale-token replacement, release fencing and legacy-schema migration.

## Validation
- Local SQLite lease and runner tests plus the full repository CI suite.
- No live YouTube API request is made.
