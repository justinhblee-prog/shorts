# BUILD-00143 — harden YouTube Analytics persistence validation

## Problem

The provider response parser rejects booleans and out-of-range retention coordinates, but `YouTubeAnalyticsStore.save()` is also callable directly by internal code and tests. Its shared `_as_number` helper previously converted Python booleans to floats, and the persistence method did not independently enforce normalized retention coordinate bounds. This left a weaker validation boundary than the provider parser.

## Changes

- Reject booleans and nulls before numeric conversion; also handle numeric conversion overflow safely.
- Revalidate elapsed-video and audience-watch ratios at persistence time, requiring finite values within 0–1.
- Keep valid average view percentage values above 100%, which may reflect replay behavior.
- Preserve existing handling for relative-retention performance values.
- Add direct-store regression tests for boolean/non-finite metrics, malformed retention points and valid replay percentages.
