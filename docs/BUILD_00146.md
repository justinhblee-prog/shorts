# BUILD-00146 — comparable cohort evidence validation

## Problem

Comparable-cohort recommendation context coerced arbitrary count values with `int(...)`, accepted booleans as counts, passed non-finite or negative medians through to the UI, and trusted a caller-supplied evidence status that could contradict the validated sample count.

## Changes

- Accept cohort records only when they are dictionaries.
- Accept sample counts only as actual nonnegative integers; reject booleans, floats and string coercions.
- Normalize cohort medians through the finite, nonnegative metric validator; malformed values become unavailable.
- Derive evidence status from the validated sample count (`no_data`, `limited`, `observed`) instead of trusting the source label.
- Keep cohort context display-only with a zero ranking adjustment.
- Add regression coverage for malformed counts, non-finite/negative metrics, inconsistent status labels and valid aggregates.

## Safety boundaries

- No recommendation ranking or ordering changes.
- No inference of demand, profitability or platform-wide performance from cohort summaries.
- No live provider/account validation is claimed.
