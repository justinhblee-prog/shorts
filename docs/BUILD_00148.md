# BUILD-00148 — recommendation exposure ingress validation

## Scope

Harden the recommendation exposure persistence boundary so malformed recommendation payloads cannot crash snapshot recording or persist invalid ranking evidence.

## Changes

- Ignore non-object recommendation rows and malformed nested trend/brand objects safely.
- Accept only non-empty string/integer trend IDs (excluding booleans).
- Reject boolean, non-finite, negative and overflowing recommendation scores instead of coercing them to zero or persisting invalid SQLite REAL values.
- Validate brand identifiers/names and deduplicate selectable brands; preserve the ten-option capture cap.
- Normalize metadata recursively to JSON-safe values, replacing unsupported and non-finite leaves with null.
- Keep recommendation score adjustment disabled; this is input-integrity hardening only.

## Validation

- Regression tests cover malformed row containers, nested objects, invalid score types and non-finite metadata.
- GitHub Actions run [43803752778](https://github.com/justinhblee-prog/shorts/actions/runs/43803752778) passed the complete `scripts/validate.sh` workflow on the code/test commit. Documentation-only commits followed; no live provider or production runtime validation is claimed.
