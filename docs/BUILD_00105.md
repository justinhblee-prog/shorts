# BUILD-00105 — ClamAV malware scan gate for renderer media

**Date:** 2026-11-16  
**Branch:** `build-00105-clamav-media-scan`  
**Base:** `integration/build-00086-00096-final`

## Change

- Added `backend/media_scanner.py` with a ClamAV CLI adapter.
- Uses an argument array (no shell), bounded timeout, and explicit exit-code handling.
- Exit code 0 is clean; exit code 1 is treated as infected; all other exit codes, missing executables and timeouts fail closed.
- Rejects missing files and symlink scan targets.
- Integrated the scan after bounded download, byte-count and MP4 signature checks, but before atomic publication to the final staging path.
- Scan failure removes the temporary artifact and does not publish the final staged filename.
- Added optional environment configuration:
  - `NEXUS_MEDIA_SCAN_ENABLED=false` (explicit opt-in)
  - `NEXUS_CLAMSCAN_PATH=clamscan`
  - `NEXUS_MEDIA_SCAN_TIMEOUT_SECONDS=120`
- Added ClamAV and freshclam packages to the shared API/worker/scheduler image.
- Documented signature initialization and refresh in `docs/OPERATOR_RUNBOOK.md`.

## Validation

Automated tests cover clean, infected and scanner-error exit codes, timeout, missing executable, symlink rejection, and the staging integration gate including temporary-file cleanup. CI result is pending.

## Operational boundary

- The gate remains disabled by default for backward-compatible rollout. Set `NEXUS_MEDIA_SCAN_ENABLED=true` only after initializing ClamAV signatures with `freshclam` and confirming the database is current.
- A missing or unusable signature database blocks staging when the gate is enabled.
- CI uses deterministic fake scanner results. It does not prove that a production ClamAV database is current or that real renderer media is malware-free.
- No production deployment, live renderer download, or real artifact scan was performed.
