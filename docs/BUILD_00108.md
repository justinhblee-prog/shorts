# BUILD-00108 — authenticated operator identity for operational audit events

**Date:** 2026-11-16  
**Branch:** `build-00108-authenticated-operator-audit`  
**Base:** `integration/build-00086-00096-final`

## Change

- Extended the per-operator credential identity introduced in BUILD-00106 to operational mutation audit fields.
- The authenticated principal now supplies the actor identity for YouTube upload reconciliation and late-success resolution.
- The authenticated principal now supplies the actor identity for TikTok private publishing and publication reconciliation.
- The authenticated principal now supplies the actor identity for recommendation experiment creation and recommendation-skip feedback.
- Queue pause and resume audit events now use the authenticated principal rather than the request body's operator ID.
- Request-body actor fields remain accepted for API compatibility but are not trusted for audit attribution.
- Added regression tests that attempt to forge actor IDs across all covered operations.

## Validation

Final-head push CI [43773950141](https://github.com/justinhblee-prog/shorts/actions/runs/43773950141) and PR CI [43773953927](https://github.com/justinhblee-prog/shorts/actions/runs/43773953927): **603 tests passed**. Tests verify the store/publisher receives the identity resolved from the credential and not the forged request-body actor.

## Security boundary

All authenticated operator tokens currently have the same operational permissions. This change binds attribution but does not introduce reviewer/publisher/admin role separation or an external identity provider. Do not treat it as full RBAC.
