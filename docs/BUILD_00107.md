# BUILD-00107 — trusted proxy-aware rate-limit identity

**Date:** 2026-11-16  
**Branch:** `build-00107-trusted-proxy-rate-limit-identity`  
**Base:** `integration/build-00086-00096-final`

## Change

- API rate-limit identity continues to use the direct ASGI peer address by default and ignores untrusted `X-Forwarded-For`.
- Added explicit `NEXUS_TRUSTED_PROXY_CIDRS` configuration for operator-controlled IPv4/IPv6 proxy networks.
- A forwarded chain is honored only when the immediate ASGI peer belongs to a configured trusted network.
- Chain parsing is bounded (4 KiB, at most 20 hops), rejects duplicate/malformed headers, and walks right-to-left through trusted hops until the first untrusted address.
- Invalid forwarded chains fall back to the direct proxy peer. Invalid trusted CIDR configuration fails API startup.
- Corrected a BUILD-00106 documentation defect: literal escaped newline sequences in the top of `.env.example` are now real line breaks, and added the trusted proxy setting.

## Validation

Tests cover default XFF rejection, untrusted peer spoofing, trusted IPv4/IPv6 proxies, multi-hop chains, malformed/duplicate/oversized headers and invalid CIDR configuration. CI pending.

## Operational boundary

Configure only exact proxy CIDRs you control. The proxy must append or overwrite forwarding metadata safely; direct access from untrusted clients must not be treated as a trusted proxy. No production proxy or deployment was configured by CI.
