# BUILD-00109 — authenticated encryption for SQLite backups

**Date:** 2026-11-16  
**Branch:** `build-00109-encrypted-sqlite-backups`  
**Base:** `integration/build-00086-00096-final`

## Change

- Added optional streaming AES-256-GCM encryption for online SQLite snapshots.
- Encrypted backups use the `.sqlite3.enc` suffix and a versioned header, random 96-bit nonce and 128-bit authentication tag.
- Uses a dedicated URL-safe base64 32-byte key from `NEXUS_BACKUP_ENCRYPTION_KEY`; key generation uses `Fernet.generate_key()` but is separate from the TikTok token key.
- CLI backup, verify and restore commands automatically use the environment key.
- Encrypted verification and restore authenticate the complete ciphertext before accepting the database. Wrong keys, tampering and truncation fail closed.
- Decryption uses bounded streaming and temporary plaintext is removed after verification/restore or any error.
- Restore still refuses to overwrite existing targets. Retention counts encrypted and plaintext backup files together.
- Fixed `.env.example` line breaks while adding the dedicated backup key.

## Operational boundary

Encryption is optional to preserve the legacy plaintext CLI behavior. Configure and securely back up the dedicated key before enabling encrypted backups; losing it makes those backups unrecoverable. Encryption does not provide off-host replication, key escrow or a production restore drill.
