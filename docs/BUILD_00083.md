# BUILD-00083 — TikTok OAuth token field validation

## Scope
Harden the OAuth token persistence boundary after the bounded-response work in BUILD-00081.

## Changes
- Require access token, refresh token and creator ID to be bounded printable ASCII strings; cap tokens at 16 KiB and creator ID at 256 characters.
- Validate scope as a bounded string and reject control characters or non-string JSON values instead of coercing arbitrary objects into strings.
- Accept only Bearer token type.
- Require expiry values to be JSON integers (not booleans, floats or numeric strings), positive and within explicit maximum lifetimes: access token 365 days, refresh token 10 years.
- Validate the entire response before encrypting or writing anything, so malformed refresh responses cannot replace the last known-good credentials.
- Add regression coverage for type confusion, oversized values, invalid lifetimes and preservation of existing tokens.

## Validation boundary
The repository CI workflow is the executable validation authority for this change. Unit tests use a controlled OAuth transport; they do not establish TikTok production OAuth compatibility, live token refresh, account authorization or publishing.
