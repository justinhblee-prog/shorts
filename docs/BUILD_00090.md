# BUILD-00090 — renewable metrics collector leases

## Problem
The YouTube Data API counter collector, YouTube Analytics collector and TikTok Display API metrics collector acquired fixed five-minute leases but did not renew them while a provider batch was in flight. A slow API request or a large batch could outlive the lease, allowing a second process to acquire the same singleton slot while the first process was still running.

## Changes
- Add expiry-aware lease renewal to all three metrics stores.
- Preserve owner/token fencing: a stale owner or a replaced token cannot renew a newer lease.
- Add a shared heartbeat helper that renews leases at a bounded interval while collection runs.
- Verify ownership immediately before writing success/failure collection state. If ownership is lost, discard the result and do not overwrite the newer collector's state.
- Always stop the heartbeat and release only the caller's own lease in a finally block.

## Validation
- Add deterministic expiry, token-fencing and stale-result-discard tests.
- Automated tests do not prove real provider latency or remote API behavior; live OAuth and metrics retrieval remain separate validation items.
