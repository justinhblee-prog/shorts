# BUILD-00090 — renewable and fenced metrics collector leases

## Problem
The YouTube Data API counter collector, YouTube Analytics collector and TikTok Display API metrics collector acquired fixed five-minute leases but did not renew them while provider batches were in flight. A slow batch could outlive its lease, allowing a second process to acquire the singleton slot while the first process was still running. A separate check-then-write window could also allow a stale collector to overwrite the newer collector's health state after losing ownership.

## Changes
- Add expiry-aware lease renewal to all three metrics stores.
- Preserve owner/token fencing: a stale owner or replaced token cannot renew a newer lease.
- Add a shared heartbeat helper that renews leases at a bounded interval while collection runs.
- Verify ownership immediately before persisting collection results.
- Fence collection-state writes inside the same SQLite transaction as the lease check, closing the check/write race.
- If ownership is lost, discard stale results and reject stale success/failure state writes.
- Stop the heartbeat and release only the caller's own lease in a `finally` block.

## Validation
- Deterministic tests cover lease expiry, owner/token fencing, stale-result discard and stale collection-state write rejection.
- Automated tests do not prove real provider latency or remote API behavior; live OAuth and metrics retrieval remain separate validation items.
