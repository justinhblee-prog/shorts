# BUILD-00027 — TikTok private-only publishing backend

**Date:** 2026-11-16  
**Status:** Backend implementation on branch; CI pending.

## Scope

- Encrypted TikTok Login Kit OAuth, one-time state, secure callback cookie, token encryption/refresh rotation and refresh lease.
- Direct Post API adapter restricted to `SELF_ONLY`; query creator info and validate the current privacy options and max video duration before initializing.
- Require latest human approval, exact approved artifact snapshot, current local policy version/date, TikTok AIGC classification and disclosure, explicit operator consent, and explicit brand-content/own-business declarations.
- Verify staged-media SHA-256 and byte length from the approved artifact snapshot, upload an immutable temporary copy, and remove it after the attempt.
- Reconcile uncertain remote outcomes before retry; never automatically duplicate a possibly successful post.
- Collect metrics only for owned/published IDs through the TikTok Display API with a separate lease. Keep YouTube and TikTok provider failures isolated.
- Add protected API endpoints and tests.

## Official API constraints

TikTok Direct Post requires creator-info lookup and the privacy option to be one of the values returned for the current creator. The app's current product policy restricts posting to `SELF_ONLY`; public posting is not enabled. TikTok says unaudited clients are restricted to private viewing, and public visibility requires a successful app audit. The `is_aigc` field carries the Creator-labeled-as-AI-generated disclosure.

## Validation boundary

CI pending. Frontend controls are not yet included in this backend task. A real TikTok developer app, approved scopes, registered HTTPS callback, encryption key, creator OAuth consent, app audit, and live account verification are external prerequisites. No real TikTok post or account data is claimed.
