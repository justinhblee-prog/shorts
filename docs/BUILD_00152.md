# BUILD-00152 — chronological production-outcome holdout ordering

## Finding
The pooled views/hour holdout inherited database ordering by recommendation exposure creation time, while its reported time boundaries and purpose describe a chronological production-outcome holdout. When operators select older exposures later, exposure order and selection/outcome order can differ, causing the holdout to include the wrong period and potentially report reversed time boundaries.

## Change
- Sort validated views/hour observations by their production selection timestamp before splitting pre-holdout and holdout periods.
- Preserve the separate within-exposure diagnostics, which remain ordered by exposure generation time.
- Add a regression test with intentionally reversed exposure and selection chronology.
