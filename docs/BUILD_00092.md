# BUILD-00092 — explicit worker offline lifecycle

## Problem
A worker that exits gracefully remained recorded as online until its last heartbeat aged beyond the stale threshold. Operational health counted any recent registry row as online, even when its stored status was offline.

## Changes
- Add an explicit, idempotent worker-offline transition that updates status and heartbeat timestamp.
- Mark the worker offline from the worker main loop's `finally` block, including normal stop, SIGTERM and handled fatal exits.
- Keep stale-heartbeat detection for abrupt process termination where cleanup cannot execute.
- Count only status=online workers with fresh heartbeats as online; stale warnings apply only to online rows whose heartbeat expired.

## Validation
- Add queue-store coverage for graceful shutdown, online/stale counters and missing worker IDs.
- Tests validate local SQLite state only; they do not simulate operating-system SIGKILL or production process supervision.
