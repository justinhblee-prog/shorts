# BUILD-00094 — clean up TikTok verified-media snapshots on idempotent returns

## Problem
The TikTok publisher created a private verified-media snapshot before checking whether a publication had already completed. The normal upload path removed the snapshot in a `finally` block, but two early-return paths bypassed that cleanup: an already-completed publication and a concurrent completion discovered by the transactional `begin` call. The first path also unnecessarily required the local staged file to still exist for an idempotent retry.

## Changes
- Return an already-confirmed publication before opening or copying the staged media.
- Explicitly unlink the losing worker's verified-media snapshot when a concurrent completion is discovered under the transactional begin operation.
- Add regression tests for both early-return paths, including proof that the race path removes its temporary snapshot.

## Validation
- Deterministic local SQLite and fake-transport tests.
- No live TikTok API or account publishing is performed.
