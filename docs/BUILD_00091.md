# BUILD-00091 — fence TikTok status polling with scheduler leadership

## Problem
The scheduler cleared its leadership token when schedule dispatch reported lease loss, but the same iteration could still enter the TikTok publication-status polling block. A former leader could therefore make unnecessary duplicate read-only provider requests after losing the singleton scheduler lease.

## Changes
- Require a live scheduler token before attempting TikTok status polling.
- Renew the scheduler lease immediately before polling and verify it remains valid after polling.
- Skip provider polling if leadership is missing or renewal fails.
- If leadership is lost during polling, report it to the main loop and clear the local token so the process returns to standby.

## Validation
- Add deterministic tests for pre-poll lease loss, successful lease-bracketed polling, leadership loss during polling and disconnected-account behavior.
- The status endpoint is read-only; these tests do not make real TikTok API calls.
