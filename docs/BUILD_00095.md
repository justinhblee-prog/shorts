# BUILD-00095 — make confirmed YouTube upload retries independent of staged-file retention

## Problem
The YouTube publisher returned an existing confirmed upload only after validating and statting the local staged media file. If operators cleaned up staged media after a successful upload, a repeated idempotent request failed even though the remote upload was already confirmed.

## Changes
- Return the existing confirmed upload immediately after validating the latest human approval.
- Keep staged-file, approval fingerprint and upload preflight validation for all new upload attempts.
- Add a regression test that deletes the staged file after a successful upload and verifies a retry returns the existing video without another YouTube insert call.

## Validation
- Deterministic fake YouTube service and local SQLite test.
- No live YouTube API request or account upload is performed.
