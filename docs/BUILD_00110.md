# BUILD-00110 — operator role-based access control

**Date:** 2026-11-16

## Implementation

- Added `backend/operator_rbac.py` with a closed, explicit permission catalog and role resolution.
- Added `NEXUS_REVIEW_ROLE_MAP_JSON`, mapping authenticated reviewer IDs to one or more roles.
- Applied role checks to review, production, media, publishing, OAuth, finance, analytics, schedules, trend collection, recommendation experiments, brand activation and queue-control operations.
- Unknown operators are denied when the role map is configured; malformed role configuration fails closed with HTTP 503.
- Multiple roles combine permissions; `admin` is the explicit wildcard role.
- Added regression tests for permission isolation, route denial before media access, unmapped identities and malformed configuration.
- Documented migration behavior and role assignments in the operator runbook and backend README.

## Migration behavior

If `NEXUS_REVIEW_ROLE_MAP_JSON` is absent or blank, the previous authenticated full-access behavior remains for compatibility. RBAC is not active until the map is configured. Once configured, any authenticated identity omitted from the map receives no role-protected permissions.

## Security boundary

This is role-based authorization layered over per-operator bearer tokens. It does not provide OIDC/SSO, browser sessions, token expiry, automated revocation or role administration UI. Operators must securely provision tokens and role maps.
